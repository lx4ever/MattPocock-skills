# 0026: Reference docs don't automatically stay current when a later lesson corrects or extends an earlier one

**From:** structural review after Lesson 24

## The finding

By Lesson 24, this workspace had one reference doc (`buyers-and-programs-cheatsheet.html`), built after Lesson 1 and never touched again. Meanwhile at least a dozen lessons since then corrected or materially extended facts it still stated the old way — DIA didn't exist in it at all, RPAS still read "MDA" instead of 49North, CC-330's superseded ISS contract note was still the only figure given, and an entire category of finding (funding/enabling-mechanism doors: DDI, CDIR, RDII, NADCAP, Team SkyGuardian) had no reference presence whatsoever despite being some of the most actionable material produced. Each individual lesson update callout (e.g. "Updated by Lesson 15" on Lesson 8) correctly flagged the lesson-to-lesson drift — but none of them touched the reference doc, which kept citing the original, now-outdated framing.

## Why it matters

The "Updated by Lesson N" callout pattern this workspace has used consistently keeps individual lessons honest relative to each other, but it doesn't propagate to reference docs, which the teach skill's own philosophy says are the artifact actually meant to stay current ("lessons will rarely be revisited later — reference documents will be"). A reference doc that's stale is worse than no reference doc, because it looks authoritative while quietly citing superseded facts.

## Follow-up

Build a habit of checking reference docs against recent lessons periodically (roughly every 5-8 lessons, or whenever asked to review/reorganize) rather than only updating them reactively. This review added two new reference docs (`hubs-and-contacts-cheatsheet.html`, `open-doors-ranked-cheatsheet.html`) precisely because an entire category of finding — the funding/access-mechanism layer from Lessons 16–24 — had accumulated with no compressed reference version at all.
